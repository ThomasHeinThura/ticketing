## Approach

**AST rewrite, not targeted regex patches — chosen deliberately, per the issue's own recommendation and this repo's established precedent (`check-deps.mjs`, `check-ui.mjs`'s #255 rewrite).**

`scripts/ci/lib/env-reads.mjs`'s detector was a hand-written character-level tokenizer (see git history) that had to re-derive comment/string/regex/JSX-text boundaries itself, and repeatedly found — and needed patching for — a new bypass shape doing so: #342's original E1/E2 (spread, `globalThis.process.env`, bracket/optional-chaining access, aliasing, `Reflect.get`, `node:process` imports, a comment between tokens — closed by #352), then #382's own further "D3" round found the *same class recurring at a narrower scope*: casts, string-literal escapes, nested destructuring, a bare-argument heuristic that both missed real cases and flagged fake ones (L1), and — the fundamental one — JSX text that merely looks like a comment or regex confusing the lexer's own grammar (H1). That review's own conclusion: "don't queue another lexer-patch round... rebuild the detector on the TypeScript compiler API... and fail on any parse error." That's what this PR does.

The detector now walks a real, parsed AST (`typescript/unstable/ast` via `typescript/unstable/sync`'s `API`, exactly as `check-deps.mjs`/`check-ui.mjs` already do for their own gates) instead of pattern-matching source text:

- `classify(node)` answers "what does this expression *denote*" — the `process` global, `globalThis`/`global`/`window`, `import.meta`, or the environment bag reachable from any of those — seeing through parens, `as`/`satisfies`/`<Type>`/`!` casts, `await`, `require`/dynamic `import` of `"process"`/`"node:process"`, `Reflect.get`/`Object.getOwnPropertyDescriptor`, and alias chains (including an alias of an alias). Closes H1, M2 and M3 as one structural mechanism rather than one exemption per shape.
- The tree walk uses that to decide, at every real property/element access, destructuring pattern, spread, assignment, module export, and (narrowly) call argument in the file, whether a read is **named** (attributable), **computed** (a dynamic key — cannot be attributed), or **alias** (the whole bag, or the bare global itself, escapes as a value). Closes M1 (a module-boundary export of the raw object) and M4 (nested `globalThis` destructuring).
- `process[X]`/`globalThis[X]`/`import.meta[X]` fails closed on anything that cannot be proven to be a *different*, plain literal or numeric index — a variable, a concatenation, a substituted template all count as reaching the sensitive member, extending an existing design decision (this gate already did this for `process["env"]`) uniformly to `globalThis`/`import.meta` too.
- A declaration binding (a parameter, a catch-clause variable) is *never* itself classified as a reference — only the values things are initialized from, or the arguments things are called with, are — which closes L1's false positives (`if (process)`, `(process) => …`, `function f(process)`, `catch (process)`) structurally: a real parser distinguishes a binding position from a reference position by node kind, a token-adjacency heuristic cannot. A narrow, additional shadow-tracking pass also handles the one case that *is* reachable through a real reference (`catch (process) { log(process); }`) — see `env-reads.mjs`'s own header and inline comments for the full account, including every documented accepted limit.

`check-env.mjs`'s real-repository scan now batches every file through one `API` instance (mirroring `check-ui.mjs`'s own `main()`), rather than one `findEnvReads(text)` call per file, and fails closed on a parse error (per #382's own recommendation) instead of silently treating an unparseable file as clean. Only *how a read is detected* changed — the comparison against `docs/05-operations/configuration-reference.md` and the baseline/ratchet logic in `check-env.mjs` are untouched.

**Verified, not assumed:** `node --test 'scripts/ci/**/*.test.mjs'` is 679/679 green (94 suites), and `node scripts/ci/check-env.mjs`'s output against this repository's real `apps/`+`packages/` source is **byte-for-byte identical** before and after this change (29 approved reads, same two informational notes) — confirmed by running the unmodified pre-PR detector against the same worktree. Zero new false positives, zero regressions.
