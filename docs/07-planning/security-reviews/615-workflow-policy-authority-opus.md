## Findings

**Blocking:**

1. **"Review records" = all of `security-reviews/**` makes historical security decisions — which product code cites as authority — editable with no review at all.** `docs/04-engineering/agent-workflow.md:192-193`: "**Review records** are `docs/07-planning/security-reviews/**` and the PR body. A commit that touches only review records needs **no new review of any kind** — not ordinary, not security." This is carried into Merge-ready (`definition-of-done.md:16`). Base required "ordinary exact-candidate review is still required" (`definition-of-done.md:138-141` at base). The CI note rule only proves that this PR's Sol note is current; it does not limit which notes are touched. Under the base rule an ordinary reviewer at the final head still saw any note edit; under the new rule nobody does. The notes are the rationale of record for live security decisions: `440-runtime-authorization-wiring.md` is cited as "for the decision" by `tests/permissions/inherited-uncovered.json:24`, `apps/api/src/invitation/policy.ts:62` and `invitation/index.ts:57`; `13-kaneo-import-lenses/E-secrets.md` (finding E-13) by `apps/api/src/instance/policy.ts:54`; and `route-classification-guard.ts:22`. Exploit: after review, a lane pushes a commit that touches only `security-reviews/`, deleting or relabelling a historical finding or rewriting another PR's decision record; the conductor's path check passes and no reviewer of any tier sees it. This also undercuts do-not 15 ("erase/relabel a historical finding") and the base CLAUDE.md rule "Do not rewrite … old security-review notes". **Fix:** define a review record as *adding* this PR's own note(s) (`<this-pr>-*.md`, Markdown only) plus the reviewer-identity and review-link fields of the PR body. Any modification or deletion of an existing note, any other PR's note, or a non-`.md` file under that directory is a reviewed change. Check with `--name-status`, allowing only `A` (or `M` of this PR's own note).

2. **The conductor's "mechanical path check" uses the net-tree comparison that CI explicitly rejects as a bypass, while calling itself the same rule.** `agent-workflow.md:194-196`: "The conductor verifies the path list mechanically (`git diff --name-only <reviewed>..<candidate>`) … This is the same rule CI enforces for security notes". CI's rule 3 in `security-review-note.mjs` (GPT-F5) is judged over *landed commits*, not the net tree — "reverting does not restore a clearance" — and it also requires that the reviewed head be an ancestor. The command contradicts `agent-workflow.md:181` ("every commit landed in between"). For reusing ordinary reviews this conductor check is the *only* control, since CI does not bind ordinary reviews. My scratch repo shows code → revert → note reading as "review-record-only"; with merge commits on `main`, the unreviewed intermediate commit lands in history. **Fix:** require `git merge-base --is-ancestor <reviewed> <candidate>` plus a per-commit listing (`git log -m --format= --name-status <reviewed>..<candidate>`) with the allow-list from Blocking 1, or defer to `reviewBinding()` semantics. Drop the "same rule" claim unless it is literally true.

3. **The explicit ban on fabricating review evidence was dropped, while the new reuse rule depends on note authenticity.** Base `AGENTS.md:292`: "Never: fabricate review evidence or mark an independent review `n/a`". It is absent from the new AGENTS.md "Never" line (231-233), all 23 do-nots and agent-workflow.md; line 257 covers only "fabricate a status". CI admits it "does not prove a review took place … a determined author can type a SHA into the note". Because the new rule removes the ordinary reviewer at the final head, a lane can push code H3 and then a note-only commit H4 declaring `**Reviewed head:** H3` with a CLEAR verdict that never happened. CI binds, the path check passes, and Merge-ready is satisfied on paper. **Fix:** restore the prohibition in AGENTS.md "Do not". Add to Merge-ready that the conductor confirms each review record against a review it dispatched or can trace (reviewer session/spawn provenance and verbatim output) before relying on it. Require that a note's verdict text be added only by the reviewer's own transport.

**Non-blocking:**

1. PR body as a "review record" (`agent-workflow.md:192`): editing `## Gates`, `## Not done`, `## Checklists` or `## Task` after review never invalidates a verdict, so a `## Not done` gap a reviewer relied on can be silently removed. Base was silent here (only a SHA change triggered re-review), so this is not a regression. ci-fast still re-runs on `edited`, and waived rows still need Thomas. Narrow the definition to the review-identity and review-link fields.
2. "Review counts unchanged" is inaccurate. `decision-log.md:32` ("every review count … Unchanged") and audit line 152 say so, but `agent-workflow.md:162` adds a new reduced tier: "Records only (status, queue, evidence) … **one** independent factual check" (base: at least two for ordinary substantive work). "Evidence" is undefined; it should explicitly exclude security-review notes, decision-log entries, active-mission.md and machine-read docs. The decision log does disclose the note-only re-review relaxation separately; qualify the "unchanged" claim.
3. **This candidate triggers its own new rule.** Row `agent-workflow.md:169` requires a "full pass" security review when a workflow change alters review requirements, and this PR does (evidence reuse, the records-only tier, the re-run allowance). Under the model policy that pass is GPT-6 Sol. CI will not enforce it (no security path touched), and audit §5 (lines 121-123) implies no security review is needed. The conductor should not merge on ordinary reviews plus this Opus review; mark it **SECURITY RE-REVIEW PENDING — GPT-6 SOL CAPACITY** if needed.
4. The bounded re-run (`error-fix-loop.md:124-127`) does not create a re-run-until-green path: one re-run, stop on the second failure, G11 sampling unchanged (lines 129-132), required checks never reused. Two gaps remain. "Per candidate SHA" resets on any records-only commit — cap it per job per task across SHAs unless a change addresses the cause, mirroring the three-attempt rule. "Network … error" (line 116) can occur inside a test, so a flaky test could be mislabelled as infrastructure (testing-strategy.md:490: "a flaky test is a broken test"); restrict eligibility to failures before test execution or in runner provisioning. The allowance is also inconsistent with lines 133-134 (changing retry counts needs its own PR and Thomas's approval) — confirm Thomas approved this specific allowance.
5. Merge-ready (`definition-of-done.md:16`) omits the pre-merge runtime proofs (exact-image boot, installer regression) that base `AGENTS.md:101-104` required before protected merge. They appear in `agent-workflow.md:276-278` but are not referenced by the merge-ready level, and the integrated-slice checklist (149-151) orders image boot after merge, as base did. Add "applicable pre-merge runtime proofs" to Merge-ready.
6. `active-mission.md` is now a level-1 authority but an ordinary docs file, and its owner provenance is whatever an agent writes into the decision log (the same risk existed in base via the decision log). Classify edits to it under the "Agent authority" row (full pass) and require a verifiable owner source. On the policy-maintainer row (`agent-workflow.md:151`) I found no bypass: CLAUDE.md:45-47 says a Claude session "is not the reviewer of record for a role the model policy assigns to another model". Even so, state in Model policy that the maintainer's own PRs get independent reviews, and Sol wherever the tier requires it.
7. The evidence-reuse inputs for test results (`agent-workflow.md:187`) omit docs read by machine checks (configuration-reference.md, identifier registers, the decision log for waivers). This is mitigated by required status checks never being reused (line 190).
8. The sampled-review packet author changed from "GPT-6 Luna or GPT-6 Sol" (base) to "another context". The Model-policy row for context preparation still names Luna and the PR template still says Luna/Sol, so this is minor.
