## Blocking finding

**Same-field optimistic updates can leave a failed value in the task cache when both overlapping writes fail.** This affects status and the equivalent assignee rollback mechanism.

In `use-update-task-status.ts:47-62`, each mutation captures its immediate optimistic predecessor, but only the latest mutation version may roll back. Reproduction:

1. Cache begins at `backlog`.
2. M1 optimistically writes `in-progress` and captures `backlog`.
3. M2 optimistically writes `done` and captures `in-progress`.
4. M1 fails while M2 is pending. Its rollback is skipped because M1 is no longer the current field mutation version. Its `onSettled` sees multiple in-flight same-task mutations and skips invalidation.
5. M2 fails. It is the current version and restores its captured predecessor, `in-progress`, even though M1 failed too.
6. M2's `onSettled` now invalidates the task query. With no active query observer, TanStack marks it invalidated but does not fetch; cache remains `in-progress` (`fetchStatus: idle`).

The assignee hook has the same capture/version/rollback structure (`use-update-task-assignee.ts:56-70`). Existing regressions cover an older failure followed by a newer success, but not this two-failure case. Invalidation does not reliably close the hole: inactive queries are not refetched by the default invalidation behavior, and an active observer can only replace the incorrect cache after the asynchronous refetch completes.

The analogous status/assignee fix should preserve the correct base state across overlapping same-field mutations (or otherwise guarantee reconciliation independent of active observers), and should have regressions for both failures and mixed success/failure orderings. I did not remediate.

```tsx
it("leaves the first failed optimistic value after both writes fail", async () => {
  let rejectFirst!: (error: Error) => void;
  let rejectSecond!: (error: Error) => void;
  vi.mocked(updateTaskStatus)
    .mockImplementationOnce(() => new Promise((_resolve, reject) => { rejectFirst = reject; }))
    .mockImplementationOnce(() => new Promise((_resolve, reject) => { rejectSecond = reject; }));
  const { result, queryClient } = setup();
  let first!: Promise<unknown>;
  act(() => { first = result.current.status.mutateAsync({ ...task, status: "in-progress" }); });
  await waitFor(() => expect(updateTaskStatus).toHaveBeenCalledTimes(1));
  let second!: Promise<unknown>;
  act(() => { second = result.current.status.mutateAsync({ ...task, status: "done" }); });
  await waitFor(() => expect(updateTaskStatus).toHaveBeenCalledTimes(2));
  rejectFirst(new Error("first failed"));
  await expect(first).rejects.toThrow("first failed");
  rejectSecond(new Error("second failed"));
  await expect(second).rejects.toThrow("second failed");
  expect(queryClient.getQueryData<Task>(["task", task.id])?.status).toBe("in-progress");
  expect(queryClient.getQueryState(["task", task.id])?.isInvalidated).toBe(true);
  expect(queryClient.getQueryState(["task", task.id])?.fetchStatus).toBe("idle");
});
```
