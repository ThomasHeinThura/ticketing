## Top 5

1. **`compose.yml` publishes 5173 and the prod overlay cannot take it back** (deployment.md:88-96) — Compose concatenates `ports:`, so the production stack still publishes the app port, which falsifies the "never published" premise that `TASKDESK_TRUST_PROXY=1` and the whole `X-Forwarded-For` story depend on (traefik-and-domains.md:51-53).
2. **SeaweedFS is shipped as a service with no service definition** (deployment.md:13,68; traefik-and-domains.md:39) — port 8333 needs master+volume+filer+S3 gateway or `weed server -s3` with an `s3.json` for credentials, plus a bucket-create step; and presigned URLs signed for the internal endpoint will not verify at `https://files.<domain>`, with the bucket's own CORS never configured anywhere.
3. **The default storage backend contradicts itself** — storage-and-attachments.md:11 says `storage.s3` is the default, one-line-install.md:47-48 and decision-log.md:160-161 say `storage.filesystem` needs no configuration at all; this decides whether SeaweedFS runs, whether `files.<domain>` exists, and whether the installer's three-host DNS pre-flight (one-line-install.md:55) can ever pass.
4. **Two false claims about kaneo** — deployment.md:142-144 and kubernetes.md:3 both say "kaneo ships separate `api` and `web` images"; kaneo's chart is explicitly "combined API + web frontend" on a single image (charts/kaneo/values.yaml:63-67) and Dockerfile.kaneo:84-118 builds one runtime image running nginx and node together.
5. **The five+six rule leaks in three directions** — `TASKDESK_FILES_URL` still cited in traefik-and-domains.md:45 after configuration-reference.md:41-42 removed it; `TASKDESK_METRICS_TOKEN` used four times in the runbook although it is God Mode config on a separate listener; and `DOMAIN`, the image digest and the HSTS switch are real `.env` entries that "the complete list" (configuration-reference.md:54) never names.
