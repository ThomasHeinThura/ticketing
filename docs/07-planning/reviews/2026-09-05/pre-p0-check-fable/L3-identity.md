## Top 5

1. **The reload mechanism watches the wrong table.** auth-runtime-reconfiguration.md:35/62/67 builds and polls only `instance_plugin_config`, but every OIDC connection is an `identity_connection` row (identity-provisioning.md:56-59, data-model.md:119) — so a God Mode Entra change never takes effect on any replica, which is the exact failure the document was written to prevent.
2. **`accountLinking` is claimed off and is on in the inherited code.** security-model.md:145 says "better-auth's auto-link defaults are off"; kaneo/apps/api/src/auth.ts:234-245 ships `enabled: true` with `trustedProviders: [… "custom"]` — the very genericOAuth provider `auth.oidc` uses. `IP-18` fails on day one unless the retrofit sets it explicitly and a test reads the config.
3. **The Entra claim floor is unbuildable as written.** `IP-9` and security-model.md:137 require `email_verified = true`, which Entra v2.0 ID tokens do not emit; the default mapping assumes an `email` claim Entra does not guarantee; `preferred_username`, `upn`, `_claim_names` and group-claim overage appear nowhere in the corpus; and the group→role editor maps group *names* while Entra sends object ids.
4. **"Revocation is immediate" is contradicted by inherited config.** `session.cookieCache { enabled: true, maxAge: 300 }` (kaneo auth.ts:556-561) serves sessions from a signed cookie for five minutes; no document mentions disabling it, so `IP-15` de-provisioning leaves live sessions.
5. **Placeholder claiming vs `IP-18`, and `both` vs "never both".** auth-and-identity.md:255-260 links a new login to an existing person **by email**, which `IP-18` and auth-and-identity.md:165 forbid; and ADR 0003:37 still grants every provider a `portal_scope` of "`agent`, `customer` or `both`" against four documents that say never both.
