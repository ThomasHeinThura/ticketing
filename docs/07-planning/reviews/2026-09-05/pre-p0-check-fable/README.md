## 2. Security and authorization — contradictions and unbuildable rules

These are the class of defect v1 died of. Fix before the router retrofit and before P1 code.

1. **CSRF check is unconditional.** `security-model.md:209`: "Every unsafe method requires `Origin` … failing that, 403." Non-browser clients send no `Origin` → every API-key, SCIM and MCP write is 403, or the implementer exempts anything without an Origin and the control is gone. → scope the Origin/Referer check to **cookie-authenticated** requests only.
2. **`orOwner` bypasses capabilities.** `rbac.md:283-285`: capability checked first, else the ownership predicate passes. So `comment:update_own`, `comment:delete_own`, `attachment:delete_own` (`rbac.md:67-73`) are never actually required — revoking them changes nothing, and the "edit window" (`rbac.md:67`) is not expressible. → the owner branch must require the `*_own` capability **and** ownership; add a time-bound predicate.
3. **Elevated DELETEs cannot both be session-only and return 202.** `rbac.md:360` (row 16) makes workspace/project/API-key/webhook/identity-connection deletion elevated; `rbac.md:368-374` refuses API keys `403 session_required` **before** policy; `rbac.md:378-382`, `api-design.md:220`, `PA-4` say every DELETE from an API key returns 202. → decide: non-session credentials get `403 session_required` for elevated targets; mark the pending-actions table accordingly.
4. **`pending_action` has no payload and no route key** (`data-model.md:301`: `payload_hash` + `payload_summary` only). `PA-6.3` "re-hashes the stored payload" and `PA-7`'s exactness guarantee have nothing to run on; for `mcp_destructive` the policy to re-run is ambiguous. → define the hash input over stored columns (action, target_type, target_ids, scope) or store `payload jsonb` + `route_key`.
5. **`is_mcp` is self-declared.** `mcp-server.md:143-147`: the flag is set by the "Use with an AI agent" flow. Any ordinary personal key pasted into `@taskdesk/mcp` bypasses `feature.mcp`, the read-only default, the write ceiling and the session-only refusal at once. → make **all** personal keys read-only by default with write as a warned opt-in; hang MCP-specific controls on properties the server can verify.
6. **`MC-7`'s destructive list is too short.** `assign_work_item`, `transition_work_item`, `update_work_item`, `add_comment`, `set_custom_field`, `log_time` need no approval, so the doc's own prompt-injection example ("reassign every ticket") succeeds one call at a time.
7. **Elevation is not in the policy shape.** The elevated and session-only lists are prose tables plus a hand-maintained test list; `Policy` has no `elevated` / `sessionOnly` field, so route coverage cannot catch a missing step-up. → add the field.
8. **`/api/public/health/deep`** = "`instance:admin` OR the metrics token" fits none of the five kinds, and the path is spelled three ways (`api-design.md:35`, `security-model.md:351`, `observability.md:122`).
9. **"The specs may use no other form" (`rbac.md:267-268`) is already false**: `(scoped)`, `(per scope)`, `owner | …`, `authenticated (any)`, `+ re-auth`, `work_item:assign | work_item:update (self)` (a body predicate the registry cannot express) are live in six specs. Worst case: `time-and-cost.md:108-109` gates PATCH/DELETE on `time_entry:read_any` → every `lead` can edit anyone's timesheet.
10. **Service-key authority is stated three ways**: `AK-3` "clamped on the next request", `AK-7` "stored subset", edge rows `:177-178` "follows the owner's status / clamped". → the edge rows describe **personal** keys; say so. Then add the ownership-transfer rule (your second message, item 1).
11. **The audit hash chain is not buildable**: "canonicalised row" is undefined; no serialization point across replicas (chain forks); `organisation_id ON DELETE SET NULL` mutates a hashed column; `audit-purge` breaks the chain head with no anchor. → define the input (ordered columns, RFC 8785 JSON, µs UTC), `pg_advisory_xact_lock` before insert, exclude mutable columns, anchor rows on purge.
12. **Route coverage "enumerates Hono's router"** sees one wildcard for `/auth/*`, whose endpoint set changes at runtime with plugin config. kaneo's inherited `mcp` and `oauth` routers fit no policy kind (the `delegated` union has no `'mcp'`). "Covered" overstates what the mechanism does.
13. **Retry semantics disagree three ways**: `PA-4` 409 / edge case "two pending actions" / idempotency "return the original response"; `MC-5` requires `Idempotency-Key` on `delete_work_item`.
14. **Confirmation levels**: "typed count *or* the phrase" is not in the enum; bulk deletion of any size stops below step-up while deleting one webhook needs step-up.
15. **The `customer` role holds `attachment:delete_own`** while three documents say customers delete nothing and the portal has no DELETE route → the seed and fixture contradict the behaviour.
16. Webhook creation is not elevated while rotating its secret is; `WH-12` "HTTPS only except a dev allowlist" contradicts `security-model.md:232/271`'s production egress allowlist; no endpoint mints the step-up token and its 5-minute life does not compose with the 15-minute action; `pending_action` records no invalidation reason; a target moved to another project is not detected (`PA-9` has no scope-change cause).
