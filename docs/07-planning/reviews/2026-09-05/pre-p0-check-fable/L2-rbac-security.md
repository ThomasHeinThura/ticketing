## Checks that came back clean

- **The `is_mcp` schema `CHECK` is expressible.** `data-model.md:103` gives `api_key` both `workspace_id null` and `person_id null` with "`CHECK` exactly one set — a workspace key is a service key with no person", so `CHECK (NOT is_mcp OR person_id IS NOT NULL)` (`AK-10`/`MC-21`) is a valid table constraint over real columns. (Its *usefulness* is undercut by the `is_mcp` self-declaration finding, but the constraint itself is buildable.)
- **Identifier hygiene is excellent.** Sampled 26 identifiers across the six files — every `resource:action` token (`webhook:manage`, `api_key:manage`, `saved_view:create`, `instance:read_audit`, `instance:manage_jobs`, `intake:triage`, `approval:decide`, `time_entry:read_any`, `work_item:escalate_priority`, …) resolves to `rbac.md`'s capability table with **zero** dangling names; every table named (`outbox`, `idempotency_key`, `scim_connection`, `import_run`, `work_item_sla_cache`, `metric_snapshot`, `job_lease`, `webhook_delivery`, `instance_setting`, `scim_group_member`, `pending_action`, `audit_log`, `api_key`) exists in `data-model.md`; `pending_action.requested/decided/executed` are in `events.md:105-107`; the audit action `project.reach_changed` is in `audit-trail.md:114`; every plugin id (`feature.mcp`, `import.mcp`, `ai.ollama`, `auth.oidc`, `storage.antivirus`, `notify.email`) is in `plugin-architecture.md`. The problems found above are semantic, not referential.
- **Numbers agree across documents.** `TASKDESK_TRUST_PROXY` is an integer hop count in all three places it appears (`configuration-reference.md:37`, `api-design.md:271`, `security-model.md:237`); the WebSocket re-check floor is 60 s in both `realtime.md:35` and `security-model.md:246`; the pending-action expiry is 15 minutes in `PA-8`, `data-model.md:301` and `MC-7`; the identity cache is 30 s, invalidation-driven, consistently.
- **Lookup order is stated consistently** as resolve scope object → check reach → check authority (`security-model.md:70-77`), matching the 404 rule (`rbac.md:244-248`) and `PA-6` step 2's re-authorisation. The only defect is the scope *source* gap recorded above, not the order.

## Top 5

1. **`security-model.md:209` — the CSRF Origin check is written as applying to "every unsafe method", not just cookie-authenticated ones.** Taken literally it 403s every API-key, SCIM and MCP write (no `Origin` header), making `PA-4` and the whole service-key surface unbuildable; taken loosely it becomes "exempt anything without an Origin", which is no CSRF protection at all. Scope it to cookie auth, in one place.
2. **`rbac.md:279-285` — `orOwner` is a pure capability bypass, so every `*_own` capability is dead.** Ownership alone satisfies the policy: revoking `comment:delete_own` or `attachment:delete_own` from a role changes nothing, and a `viewer` can still edit and delete their own rows. Make the owner branch require the `*_own` capability as well.
3. **`rbac.md:368-374` vs `rbac.md:378-382` / `api-design.md:220` — elevated DELETEs are session-only *before* policy runs, yet "every DELETE from an API key or MCP returns 202".** Workspace, project, API-key, webhook and identity-connection deletions cannot do both. Pick one and mark the pending-actions confirmation table accordingly.
4. **`pending-actions.md:72-81` vs `data-model.md:301` — `PA-6`'s re-hash and `PA-7`'s exactness guarantee have no data behind them.** The payload is never stored (only `payload_hash` and a render summary), and no `route_key` is stored, so the server can neither re-hash nor know which policy to re-run — ambiguous outright for `mcp_destructive`. Add `payload jsonb` and `route_key`.
5. **`mcp-server.md:142-147` — `is_mcp` is a self-declared label on a credential, not a property of the channel.** Creating an ordinary personal key and pasting it into `@taskdesk/mcp` bypasses `feature.mcp`, the read-only default (`AK-9`/`MC-16`), the MCP write ceiling, `MC-22`'s stricter limits and rbac.md:372's session-only refusal — all at once. Move those controls onto verifiable properties.

*(Two more that only just missed the cut: `AU-15`'s hash chain has no stated serialization point, so concurrent writers across replicas fork it and `audit-verify` reports tampering on a healthy instance — `security-model.md:334-336`; and `rbac.md:267-268`'s "the specs may use no other form" is already false, with six other policy spellings live in the feature docs.)*
