## Blocking finding

### [P1] Generic substitution is keyed by spelling, causing unbounded self-substitution

`resolveDatabaseType` checks `substitutions.get(nameNode.name)` at `scripts/ci/check-queries.mjs:216-225` and follows that value with the same substitution map. On each alias use, lines 241-257 copy the map and assign an inner parameter by **name**. If both the outer and inner identity alias call their parameter `T`, the inner `T` maps to its argument `T` while overwriting the outer binding. Resolving it repeatedly finds itself; the alias-binding visited set is never reached.

This valid TypeScript source throws `RangeError: Maximum call stack size exceeded` from `queryReadViolations`, rather than returning a finite finding list:

```ts
type Id<T> = T;
type Wrap<T> = Id<T>;
function f(x: Wrap<string>) { return x; }
```

The same chain instantiated with the registered `DbTransaction` also throws rather than reporting the protected `tx.select()` lookup. The first minimal case contains **no database operation**: any future valid API parameter of this form can crash `pnpm check:queries` and make the required gate unusable. Distinct parameter names (`Wrap<U> = Id<U>`) work, showing that this is lexical binding identity, not a genuinely recursive type alias. Cycle detection for `type A = B; type B = A` terminates, but it does not cover this substitution cycle. Resolve parameters by declaration/scope identity or equivalent lexical frames, and add both ordinary and registered-root nested identity regressions that return a finite result.

## Additional finding

### [P2] Function type-parameter shadowing is treated as the imported root

`collectStaticBindings` creates a function scope at lines 400-428 but does not register `node.typeParameters` in that scope's `typeBindings`. The resolver then walks outward to the registered import. For the valid source below, TypeScript's inner `DbTransaction` parameter shadows the import and is unconstrained; the checker nevertheless reports `select`:

```ts
import type { DbTransaction } from "../events/outbox";
function f<DbTransaction>(tx: DbTransaction) { tx.select(); }
```

This is a false positive in the new lexical type-namespace contract. Local type-alias shadowing already works, so function/class type parameters should likewise shadow registered roots without being inferred as database executors. It is not present in the current API source, but belongs in the same structural remediation as the P1 binding flaw.

## Disposition and limits

The prior 6d P1 simple alias bypass is repaired for its direct form: imported `DbTransaction`, imported `DatabaseInstance`, and known structural transaction types retain identity through one/chained local aliases; explicit/default simple identity generics work. The checker still documents a bounded static scope and does not claim arbitrary TypeScript evaluation, dynamic imports or interprocedural inference. The failures above use the bounded, statically known identity and lexical-shadow cases the new contract explicitly claims.

The live source scan passing means only that current API source does not exercise these counterexamples; it does not validate the gate against future valid source. The prior ordinary/auth/SLA/OpenAPI/hosted/runtime findings and required PR checks remain separate, with no waiver or transferred approval. **Do not merge c993 as a cleared security-control candidate.** Review a corrected exact head at the required tier after the author resolves the structural binding issue.
