# UX critique of local SIT — 8 Nov 2026

Seven design reviewers looked at 60 screenshots from local SIT (staff admin and customer; 1440 px dark and light, 390 px phone dark) and the matching code. A second reviewer checked each high and medium finding against the screenshot and code (verdicts: confirmed, unclear, refuted). Fixes are planned as roadmap rows UX-0 to UX-9.

**Limits.** The light-mode captures were identical to dark (the capture never switched theme), so light mode is unreviewed. The demo database has reports, catalogue and SLA switched off, so those screens show only an "off" message and their charts and tables were not judged. Calendar, timeline, cycles and modules are off for the demo project. Fixing both is row UX-0.

## Core work screens

I looked at every core work screen at 1440 dark, 1440 light and 390 dark. The Board and Table layouts come closest to finished. The List layout, which is the default, is noisy: each row repeats its status, the unassigned marker is a bare "?", and rows carry none of the service-desk signals an agent needs (SLA, requester, age). The Backlog page is a separate hand-built table with its own header, its own badge style, arrow-button ordering instead of drag, and columns that do not line up between groups. Cycles and Modules show a plain line of text at the top of an empty page, with no icon and no action. The phone layout is the weakest: the toolbar wraps onto 3 rows, the project name and tabs are hidden, list titles are cut to about 12 characters, and the Table and Backlog columns are cut off with no way to scroll to them.

Two problems with the screenshot set itself:
1. The ui-1440-light files are identical to the dark ones. MD5 hashes match for work, backlog and my_work, and the light board file differs in hash but still renders dark. So light/dark parity could not be judged. Either the capture never switched theme, or a saved per-user dark theme overrides prefers-color-scheme. Check this before trusting any light-mode result.
2. work_layout_calendar and work_layout_timeline are byte-identical to the List screenshot. ?layout= only accepts board, list or table (apps/web/src/lib/work-item-list-search.ts:292), and Calendar and Timeline are off for HELP (feature.calendar and feature.timeline in apps/web/src/components/common/header/project-layout-controls.tsx:154-155). Cycles and Modules are off too, so the demo project hides those four views, and none of them was actually reviewed.

customer_backlog is a correct portal 404, not a defect.

## Project hub and agent home

I looked at all 20 admin_agent screens in this group at 1440 dark and checked the key ones on phone (390 dark). Two gaps limit the review. First, the ui-1440-light files are byte-identical to the dark ones (same MD5 for triage, inbox and HELP_work), so light/dark parity was never captured and cannot be judged. Second, admin_agent_projects.png is not the projects list: it is the URL /agent/projects, which shows TanStack's bare "Not Found" text. The sidebar's Projects entry links to /agent, which was not captured, and neither was the project Overview tab. So the projects list and the project status page could not be reviewed and need a new capture.

What works: the Work items board and list come straight from Kaneo and look like a finished product. Documents is a good pattern for a register page.

What looks basic falls into four patterns. (1) Agent home screens are thin text lists. The sidebar has no icons and no counts, Triage is a plain table with no priority, SLA or row actions, and My work is a dead end for a lead with 6 unassigned items. (2) Several pages are form-first. Saved views and Timesheet put a creation form above the content, and Timesheet hides the week grid entirely when it is empty. (3) Empty and feature-off states are bare centred text with no next step. (4) The SIT seed shows test data ("[audit]", "Matrix 6 Nov", raw markdown excerpts, role names in brackets after people's names), which makes every screen look unfinished. Phone layouts clip tables (Triage, Backlog) and stack the Work toolbar into 3 rows. Most fixes reuse existing Kaneo pieces (sidebar menu icons and badges, the list view, EmptyState, the board grid) and need no new components.

## Service management and reporting

Service management and reporting group, judged from 21 screenshots (1440 dark, 1440 "light", 390 dark phone) plus the code. The main problem is not styling. In the seeded local SIT, feature.reports, feature.service_catalogue and feature.sla are all off. So Reports, Services, Change calendar, Announcements and SLA policies show only an "X is off" message. A service-desk manager sees no charts, tables or SLA data anywhere, which goes a long way to explain why these screens look "very basic". Charts, report tables, the services list and the SLA editor could not be judged visually at all, so a re-capture with the flags on is the first step. Even the off states use three different patterns: an Alert banner on Reports, a centred empty block on Services, Announcements and SLA, and an empty block inside a live calendar card on Changes. None of them gives an admin a link to Features. The pages also break their own rules: "Create managed service" is offered while the catalogue is off, the Services page loses the section tabs its sibling pages keep, the Changes page draws calendar navigation and a colour legend around nothing, and the SLA policies settings page is reachable by URL while hidden from the settings nav. Request types is the only fully live admin screen here. It opens straight into a large Create form, asks for a raw "Default project ID", and has a disabled "Save group order" button that dominates the left column. The Knowledge base is the most finished screen: a clean Kaneo table. It still has seed names with roles in parentheses, an empty Review due column, filter labels and fields that don't line up, and on phone a table cut down to a truncated Title column. Evidence gap: every file in ui-1440-light rendered in dark mode, so light/dark parity is unverified and the light capture must be redone.

## Customer portal

I reviewed the customer portal from the screenshots in ui-1440-dark, ui-1440-light and ui-390-dark, and checked the code under apps/web/src/routes/portal and components/portal.

**What works:** the portal uses Kaneo components throughout and light/dark parity is good. The requests table carries real data, and the KPI cards and status badges are a sound base.

**Why it reads as basic:**
- **Weak hierarchy.** Too many buttons of equal weight sit side by side. The white "Get help" button competes with "New Request" in dark mode.
- **Repeated columns.** "Created by: You", "Assigned to: Your team", Project and "Not set" repeat on every row.
- **Bare empty states.** Approvals shows one line of text; Announcements has no icon and nothing to do next.
- **Thin catalogue.** Two plain text cards with no icons, no help-article search and no "popular" section. A ServiceNow or WSO2 portal leads with search, then category tiles, then open requests.
- **Settings page.** The sidebar says "Settings" but the page holds only email preferences, with two disabled-looking save buttons.
- **Inconsistent page frames.** Pages switch between max-w-4xl and max-w-6xl, and headings between text-lg, text-xl and text-2xl. The left edge and title size jump as you move between pages.
- **Phone layout.** On My Requests the first request appears about 500px down, after 4 header buttons and 5 filter controls.

**Screens with no real screenshot:** customer_settings, customer_backlog and customer_knowledge_base all show "Page not found". The capture script used the wrong paths; the real ones are /account, /requests?view=backlog and /kb. So the knowledge base and backlog views were not reviewed and need re-capturing.

**Possible bug:** /settings returns 404 even though the sidebar item is labelled "Settings". AGENTS.md says old links must be kept, so this may want a redirect to /account.

**Not found in this capture:** SLA or "waiting on you" signals do not show in the list rows. portal-case-table renders PortalSlaStatus, so either the seed has no SLAs or the cue is too faint; I could not tell which.

I looked at all 50 dark-mode phone screenshots (390px) in /Users/heinthura/.taskdesk/ui-390-dark. Most screens don't scroll sideways and don't fully break, but very few are usable on a phone. Four patterns cause most of the problems.

1. The things that identify a row get squeezed out by controls or badges:
   - Workflow states: the state name is not visible at all.
   - List and table views: ticket titles are cut to about 15 characters.
   - Documents, team and members: names are cut off.

2. Toolbars wrap onto 2 or 3 rows. This pushes the first real content down by 150 to 400px, and portal Support Requests is the worst case.

3. Project screens show no project name or view name. The header is just two icons.

4. Page margins differ from screen to screen, and some settings pages add their padding twice. A phone screen has no width to spare for that.

The triage queue, the agent's most important screen, is a wide table that scrolls sideways and shows only the reference and summary.

Some problems I saw are not phone-specific, so they are outside this group:
- /agent/projects and /dashboard/settings/workspace/import show a raw, unstyled "Not Found". There is no route file for either.
- The customer screens for knowledge base, backlog and settings show "Page not found".
- The calendar and timeline screenshots are the same image as the list view. The capture script passed ?layout=calendar and ?layout=timeline, which the work route does not support.

These look like capture-script URLs, not app bugs, but someone should check them.

## Design system

Design-system review of TaskDesk. I looked at 31 screenshots across the three folders: agent work surfaces, project tabs, workspace and project settings, portal pages, and phone views.

The base is sound. The Kaneo shell, sidebar, board, list, table and settings rows look finished. The "basic and ugly" impression comes from TaskDesk-added screens that skip a shared layer:
- There is no shared page header or content container, so title size, left edge and width change on every screen.
- Feature-off and empty states are built at least five different ways.
- Priority and severity are drawn four different ways, and the status colours do not follow their meaning.
- Button hierarchy is inconsistent: disabled buttons look like grey slabs, and several primary actions compete on one screen.
- Agent data tables do not adapt at phone width.
Fixing these at the packages/ui level lifts every screen at once. Findings are ranked by how many screens each one touches.

Capture caveats:
- 36 of the 47 admin "light" PNGs are byte-identical to their dark versions. The agent app probably kept the admin's stored, server-synced theme instead of the emulated light scheme (user-preferences-sync / theme-provider). So light/dark parity was judged only on customer_* screens and the board (which also stayed dark). Recapture admin light with the theme preference reset before judging it.
- customer_knowledge_base and customer_settings show 404s because the capture used the wrong URLs. The real routes are /kb and /account. They are excluded from findings and scores.
- Seed data makes every screen look unfinished: "[audit]" and "SIT:" titles, "Matrix 6 Nov" requests, role suffixes in display names like "Grace Hopper (Service Desk Agent)". Clean the demo seed before UAT screenshots. That is a data fix, not a design one.

Where the portal is a good model: dashboard KPI cards, the case table that collapses on phone, and its styled 404.
