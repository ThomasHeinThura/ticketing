## Two audiences, two documentation sets

This is the distinction that matters, and getting it wrong produces a site that serves
nobody.

| | `docs/` (this corpus) | `apps/site` (the website) |
| --- | --- | --- |
| Audience | Us, and AI agents building it | Users, administrators, integrators |
| Answers | "Why is it built this way?" | "How do I do this?" |
| Contains | ADRs, specs, process, risks | Guides, references, tutorials |
| Lives | In the repository, read as markdown | Published at `docs.<domain>` |
| Written | Before the code | After the feature works |

They are not the same content in two places. A user does not need to know why we chose
lazy SLA evaluation; they need to know how to author an SLA policy.

## Principles

1. **Task-oriented, not feature-oriented.** "Set up SLAs for a support project", not
   "The SLA module". People arrive with a task.
2. **Screenshots, kept current.** Generated by Playwright against the seeded dataset in
   CI, so they cannot go stale. This is worth the setup cost — stale screenshots are worse
   than none.
3. **Copy-pasteable.** Every command and configuration block runs as written.
4. **Answer the question, then explain.** The answer in the first paragraph; the reasoning
   after.
5. **Say what it does not do.** "TaskDesk is not a CMDB" saves an hour of someone's
   evaluation.
6. **Search that works.** Fumadocs ships full-text search; it must be good, because it is
   how most people actually navigate.

## What gets a page

| Deserves a page | Does not |
| --- | --- |
| Every God Mode section | Every button |
| Every identity provider type | Internal architecture |
| Every feature flag | Our roadmap |
| Every migration source | Our process |
| Every capability | ADRs |

If a user cannot act on it, it belongs in `docs/`, not on the site.

## The API reference

Generated from the live OpenAPI document, not hand-written.

```
CI → export /openapi.json → apps/site/public/openapi.json → Scalar
```

A hand-written API reference is wrong within a month. This one cannot drift, because it is
the same document the server serves.

## Deployment

- Static export, deployed on merge to `main`.
- `docs.<domain>`, behind the same Traefik.
- Versioned by product major version once there is more than one.
- Storybook published alongside at `ui.<domain>`.

## Feedback

Each page carries "Was this helpful?" and an "Edit this page" link to the repository.

The unhelpful-page report is genuinely useful: it identifies the pages people read and
still leave confused, which is a better signal than page views.
